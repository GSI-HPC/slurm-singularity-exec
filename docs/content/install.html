Build the plugin against your Slurm release. Then install it on each host that runs a Slurm command or starts tasks.

Requirements

  • Slurm 26.11 or later. Earlier releases do not have the runtime plugin interface.
  • The configured source tree of that Slurm release. It is the directory where ./configure ran. The plugin includes internal headers of Slurm, which the Slurm packages do not install.
  • A C compiler, meson 1.1 or later, and ninja.
  • Apptainer on the compute nodes. SingularityCE is also possible, see Executable.

Build

$ meson setup build -Dslurm_source=/path/to/slurm --prefix=/usr --libdir=lib64
$ meson compile -C build
$ meson install -C build

meson install writes runtime_apptainer.so into <libdir>/slurm. If the PluginDir of your cluster is a different directory, set it with -Dplugindir=/path/to/plugins.

Build the plugin again for each Slurm update. Slurm loads a plugin only if the plugin was built for the same Slurm version, the patch level included. A plugin for 26.11.0 does not load into 26.11.1.

Where to install

HostWhy
Submit hostssrun, sbatch and salloc load the plugin to get its options.
Compute nodesslurmstepd loads the plugin to start the tasks. srun in a batch script loads it too.
ControllerNot necessary. slurmctld does not load runtime plugins.

Check the installation

List the runtime plugins that Slurm finds. Then show the options of the plugin.

$ srun --runtime=list
Runtime plugin types are...
	apptainer
	oci
	none
$ srun --runtime=apptainer --help
...
Options provided by runtime/apptainer:
      --container=image       Container image, or "none" for no container
      --apptainer-bind=src[:dest[:opts]],...
                              Bind paths to add to the container
      --apptainer-args=args   Arguments to add to "apptainer exec"
      --apptainer-no-default-binds=yes|no
                              Leave out the bind paths of the site
