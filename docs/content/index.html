Why a runtime plugin

Built on the interface that Slurm made for this.

Slurm 26.11 adds runtime plugins. They register options in the commands and start the task as the last step of the launch. This plugin is the next generation of the SPANK plugin slurm-singularity-exec.

01

Native options

--container is an option of srun, sbatch and salloc. The image shows in scontrol and in the job record.

 02

The complete task launch

Limits, TaskProlog, task prolog and TMPDIR apply to a task in a container as to a task on the host.

 03

Steps follow the job

A step runs in the image of its job. One step selects a different image, or none, with one option.

 04

MPI with PMIx

The tasks in the container connect to the PMIx server of the step. No bind path is necessary for this.

 05

Site defaults

apptainer.conf sets bind paths, arguments, a default image and a wrapper program for the cluster.

 06

Tested on real clusters

52 end-to-end tests run on sind clusters with Slurm 26.11 on each push.
Quick start

From the source to the first job.

The plugin compiles against the Slurm release that loads it. One parameter makes it the runtime of the cluster.

  1. Build and installCompile the plugin against the configured Slurm source tree, on the submit hosts and the compute nodes. Install
  2. Select the runtimeSet DefRuntimePlugin in slurm.conf. Select the runtime
  3. Set the site defaultsPut the bind paths of the cluster into apptainer.conf. Configuration
  4. Run a jobGive an image to srun, sbatch or salloc. First job
$ meson setup build -Dslurm_source=/usr/src/slurm --prefix=/usr --libdir=lib64
$ meson install -C build
DefRuntimePlugin=runtime/apptainer
$ srun --container=/images/alma9.sif cat /etc/os-release
$ sbatch --container=/images/alma9.sif job.sh
