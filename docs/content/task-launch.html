The plugin replaces only the last step of the task launch: the exec of the program. All steps before it run as for a task without a container.

The launch of one task

slurmstepd starts one process for each task. Before the process becomes the program of the user, it does these steps, as the user of the job.

What the SPANK plugin lost

A SPANK plugin has no hook for the exec of a task. slurm-singularity-exec used the last hook before it, task_init, and called exec there. The process became Apptainer in step 5, and slurmstepd did not do the steps after it:

StepEffect for a task in a container of the SPANK plugin
TaskPrologThe script of the site did not run. Its variables and its output were not there.
--task-prologThe script of the user did not run.
TMPDIRSlurm did not make the directory.
LimitsThe task had the limits of slurmd, not those of the submit shell.

The SPANK plugin also started a shell script between Slurm and Apptainer, which built the command line from variables.

What the runtime interface changes

Slurm 26.11 adds runtime plugins. slurmstepd calls runtime_p_run() of the selected plugin at the point where it calls execve() for a task without a container. The plugin has two results:

  • It replaces the process with the container runtime. runtime/apptainer does this for a step with an image.
  • It returns ESLURM_NOT_SUPPORTED. slurmstepd then starts the program itself. runtime/apptainer does this for a step without an image.

Thus the plugin is safe as the default runtime of a cluster: a job without --container does not change.

The command name

In step 8, slurmstepd replaces a command without a directory, for example python3, with the path of that program on the host. The image can have the program in a different directory, or only the image has it.

The plugin keeps the command name as the user wrote it: slurmstepd calls runtime_p_task_init() before step 1, and the plugin stores the name there. It gives this name to Apptainer, which searches it in the PATH of the container.

Proof

The end-to-end tests run a probe as a task in a container. The probe prints the properties that the SPANK plugin lost.

$ export WEIRD='a b"c$d'
$ ulimit -S -s 4096
$ srun --container=alpine.sif ./probe.sh
os=alpine in=alpine.sif rank=0 tp=set stack=4096 weird=[a b"c$d] cwd=/home/alice
WordShows
os=alpineThe task is in the image.
tp=setThe TaskProlog of the cluster set its variable.
stack=4096The task has the stack limit of the submit shell.
weird=[a b"c$d]A variable with a space, a quote and a dollar sign arrives without change.
