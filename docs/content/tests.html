The project has unit tests for the command line builder and end-to-end tests on real Slurm clusters. GitHub Actions runs them on each push.

Unit tests

The unit tests cover src/command.c: the word splitting, the sequence of the arguments, and the errors. They need only a C compiler. CI runs them a second time with the address and undefined behaviour sanitizers.

$ mise run test
$ mise run test:sanitize

End-to-end tests

The end-to-end tests submit jobs to a Slurm cluster and examine the results. The cluster is a sind cluster: Slurm in Docker containers, with one controller and two workers.

$ mise run e2e

The task builds the node image with the plugin, creates the cluster, builds an Alpine Linux test image, runs the tests, and deletes the cluster.

Two clusters

CI runs all tests on two clusters. They differ in DefRuntimePlugin:

  • runtime/apptainer: the plugin is the default runtime, the recommended setup.
  • runtime/oci: the default of Slurm. The tests select the plugin with the *_RUNTIME variables and with --runtime.

The node image

sind has node images for released Slurm versions. For Slurm 26.11, the project builds its own node image: the sind image of Slurm 26.05 with Slurm 26.11, Apptainer, and the headers of the configured Slurm source tree. CI builds it when image/ changes and stores it in the GitHub Container Registry.

$ docker pull ghcr.io/gsi-hpc/slurm-runtime-apptainer/sind-node:26.11

The image is also a build environment for the plugin: it has meson, ninja, a compiler and the headers in /usr/src/slurm.

Run on one node without Docker

The tests also run on a host that is a Slurm node itself, for example a virtual machine with Slurm 26.11. Set E2E_BACKEND=local. See the comment at the top of tests/e2e/helpers.bash.
