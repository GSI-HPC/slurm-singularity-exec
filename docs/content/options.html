The plugin adds four options to srun, sbatch and salloc. Each option has an input variable for each command.

OptionVariable in a jobFunction
--container=IMAGESLURM_CONTAINERRun the tasks in this image. none selects no container.
--apptainer-bind=SPEC,...SLURM_APPTAINER_BINDAdd bind paths, in the format of apptainer exec --bind.
--apptainer-args=ARGSSLURM_APPTAINER_ARGSAdd arguments to apptainer exec.
--apptainer-no-default-bindsSLURM_APPTAINER_NO_DEFAULT_BINDSLeave out the bind paths of the site.

Write each option with an equals sign: --container=IMAGE. Slurm does not accept --container IMAGE for an option of a runtime plugin.

--container

The image is a value that apptainer exec accepts: a SIF file, a sandbox directory, or a URI such as docker://almalinux:9. A path must be valid on the compute nodes.

$ srun --container=/images/alma9.sif hostname
$ srun --container=docker://almalinux:9 hostname

With a URI, Apptainer gets and converts the image on each node before the task starts. A SIF file on a shared file system starts faster.

--container=none starts the tasks without a container. Use it when the job or the site sets an image and one step must run on the host.

Input variables

Each command reads the options from variables, as it does for its other options. An option on the command line replaces the variable.

$ sbatch job.sh

Variables in a job

A job that uses the plugin has the SLURM_* variables of the first table in its environment. srun reads them, thus the steps of a job use the options of the job. See Steps of a job.

$ sbatch --container=/images/alma9.sif --wrap 'echo $SLURM_CONTAINER'
$ cat slurm-4712.out
/images/alma9.sif
