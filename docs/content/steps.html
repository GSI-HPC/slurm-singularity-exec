A step uses the options of its job. An option of srun replaces the value of the job for that step.

The image

$ salloc --container=/images/alma9.sif -n4
$ srun ./a                                    # in alma9.sif
$ srun --container=/images/rocky8.sif ./b     # in rocky8.sif
$ srun --container=none ./c                   # on the host

The same applies to the steps of a batch job. A batch script in a container needs the Slurm commands in the container, see srun in the batch script.

Bind paths and arguments

The same rule applies to --apptainer-bind, --apptainer-args and --apptainer-no-default-binds. A value of the step replaces the value of the job. It does not add to it.

$ salloc --container=/images/alma9.sif --apptainer-bind=/lustre
$ srun ls /lustre                               # /lustre is there
$ srun --apptainer-bind=/scratch ls /lustre     # only /scratch is there: error
$ srun --apptainer-bind= ls /lustre             # no bind path of the job: error

An empty value removes the value of the job.

The runtime

A job that uses the plugin sets SRUN_RUNTIME=apptainer in its environment. Thus the steps of the job use the plugin too, also on a cluster where a different runtime is the default. A --runtime option of srun replaces it.

Heterogeneous jobs

Each component of a heterogeneous job can have its own options. The variables of a component have the suffix _HET_GROUP_n, for example SLURM_CONTAINER_HET_GROUP_1. srun does not read these variables: give the options to each srun in such a job.
