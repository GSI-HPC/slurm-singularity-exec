A container sees the directories that Apptainer binds by default and the bind paths of the site. You can add bind paths and arguments for your job.

--apptainer-bind

The value is a list of bind specifications, with commas between them. Each specification has the format of apptainer exec --bind: src[:dest[:opts]].

$ srun --container=/images/alma9.sif --apptainer-bind=/lustre ls /lustre
$ srun --container=/images/alma9.sif --apptainer-bind=/data/run7:/input:ro ls /input

If you give the option more than once on one command line, the lists add up.

$ srun --container=/images/alma9.sif \
       --apptainer-bind=/lustre --apptainer-bind=/cvmfs,/scratch ./a

Bind paths of the site

The administrator can set bind paths for all containers with Bind in apptainer.conf. Your bind paths come after them on the command line of Apptainer.

--apptainer-no-default-binds leaves out the bind paths of the site for your job. The option without a value means yes.

$ srun --container=/images/alma9.sif --apptainer-no-default-binds ./a

This option does not change the directories that Apptainer binds by itself, such as the home directory. Use --apptainer-args=--no-home or --apptainer-args=--contain for that.

--apptainer-args

The value is a list of arguments for apptainer exec. The plugin splits it into words like a shell does, with single quotes, double quotes and the backslash. It does not expand variables.

$ srun --container=/images/cuda.sif --apptainer-args=--nv nvidia-smi
$ srun --container=/images/alma9.sif --apptainer-args="--env GREETING='hello world'" ./a

If you give the option more than once on one command line, the arguments add up.

A site can refuse this option with AllowUserArgs=no. The step then fails with --apptainer-args is not permitted on this cluster.
