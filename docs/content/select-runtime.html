Slurm uses one runtime plugin for each job. Make runtime/apptainer the default of the cluster, or let the users select it.

Default of the cluster

This is the recommended setup. All options of the plugin are then available in each command, without more steps for the user.

DefRuntimePlugin=runtime/apptainer

A job without --container runs as before: the plugin gives the task back to Slurm, which starts it on the host. Users can select a different runtime for a job, for example --runtime=oci.

Environment of the users

If the default must stay runtime/oci, set these variables for the users who use Apptainer, for example in a module file or in /etc/profile.d.

export SRUN_RUNTIME=apptainer SBATCH_RUNTIME=apptainer SALLOC_RUNTIME=apptainer

Option of a command

--runtime=apptainer selects the plugin for one command. In Slurm 26.11, this method has limits:

Command lineResult
srun --runtime=apptainer --container=IMAGE --apptainer-bind=/lustreWorks.
sbatch --runtime=apptainer --container=IMAGEWorks.
sbatch --runtime=apptainer --apptainer-bind=/lustre
salloc --runtime=apptainer --apptainer-bind=/lustre		Error: unrecognized option. The same occurs in #SBATCH lines. Use SBATCH_RUNTIME or SALLOC_RUNTIME, or the variable of the option, for example SBATCH_APPTAINER_BIND.
srun --container=IMAGE --runtime=apptainerThe task runs on the host. Slurm gives --container to the runtime that is selected when it reads the option. Put --runtime first.

These limits are in the option parser of Slurm, not in the plugin. They do not occur with the two methods above. See Notes on Slurm 26.11.

Which runtime does a job use

Slurm shows the runtime of a command with -v:

$ srun -v --container=/images/alma9.sif true 2>&1 | grep runtime
srun: runtime             : runtime/apptainer
