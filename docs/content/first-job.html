This page shows a task in a container, then a batch job. The examples use an AlmaLinux image at /images/alma9.sif.

The examples are for a cluster where runtime/apptainer is the default runtime. If it is not, select it first: export SRUN_RUNTIME=apptainer SBATCH_RUNTIME=apptainer SALLOC_RUNTIME=apptainer. See Select the runtime.

Get an image

Apptainer builds an image file from a container registry.

$ apptainer build alma9.sif docker://almalinux:9

Put the image on a file system that the compute nodes can read.

Run a task

$ srun --container=/images/alma9.sif cat /etc/redhat-release
AlmaLinux release 9.6 (Sage Margay)

Each task of the step starts in a container of its own. The environment and the limits are those of a task without a container. The working directory is the same too, if the container has that directory.

$ srun -N2 -n4 --container=/images/alma9.sif hostname
lxbk0719
lxbk0719
lxbk0720
lxbk0720

Submit a batch job

With --container, the batch script runs in the container.

#!/bin/bash
#SBATCH --container=/images/alma9.sif

cat /etc/redhat-release     # the script is in the container
./solver input.dat
$ sbatch job.sh
Submitted batch job 4711

To start steps with srun in the script, read srun in the batch script first.

See the image of a job

Slurm keeps the image in the job record.

$ scontrol show job 4711 | grep Container
   Container=/images/alma9.sif
